2026-09-12T11:08:14.275Z · rejected · 1m 17s · 108,518 ET

## Summary

Enriched-spec.md is faithful to spec.md/accs.md, but accs.bash under-checks the jsonl contract — it only confirms an issueId exists, not the full required shape.

## Scope of the fix

Redo the ACCS only.

## Why rejected

- **Coverage** "if ! grep -q "\"issueId\":\s*\"\?$id\"\?" "$JSONL_PATH" 2>/dev/null && ! jq -e --arg id "$id" '.issueId == ($id|tonumber) or .issueId == $id' "$JSONL_PATH" >/dev/null 2>&1; then" — This only proves an issueId is present somewhere in the file. It never asserts each line actually has reply, priority, effortEst, and a meta object with timeInMs/etConsumed/llmConfig, which is exactly what spec.md's 'Classification entry includes...' and the enriched spec's own 'Done when' bullet require. A dev agent could ship jsonl lines with nothing but an issueId and still pass this ACCS.

## Should fix

- **Coverage** priority (0-5) and effortEst (1-3) ranges from spec.md are never validated against the jsonl entries. Out-of-range values would slip through undetected.
- **Method** "marker_present_on_github" — Only checks the comment body starts with the marker prefix, never that the prose reply + table actually follow it. A comment that's just the marker line would still pass.

## Worth to consider

- **Scope** "[ -f .env ] && set -a && source .env && set +a" — accs.md's 'mock instances only' guarantee depends entirely on .env already pointing at the mock; the script never forces or overrides the GitHub target itself, so it inherits whatever's ambient rather than guaranteeing it.
- **Coverage** "Should REPOSTED also happen for prod GitHub (comment deleted by a human), or only conceptually matter for the mock's cold-restart case?" — Left as an open question rather than resolved — fine for now, but worth closing in the next breakpoint since it affects prod behavior later.
