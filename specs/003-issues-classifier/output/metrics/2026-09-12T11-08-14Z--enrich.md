# Enrichment report — 003-issues-classifier

2026-09-12T11:06:24.828Z · written · 1m 49s · 129,247 ET

## Assumptions made

- **What CLI shape does the classifier run under?** pnpm classify --spec-id <specId>, a single pass, matching the non-daemon style of the rest of the SDD tooling
- **How does GENERATED_DIR interact with the classifications path?** $GENERATED_DIR/<specId>/classifications.jsonl, default GENERATED_DIR=.generated, fully overridable so ACCS can redirect to a temp path and delete it after
- **Exact shape of the marker used for idempotency** first line of the comment, literal `<!-- classifier:<specId>:<issueId> -->`, followed by the prose answer and the markdown table

## Expected drawbacks

- Marker-based detection can be spoofed by anyone manually posting a comment starting with the exact marker string, causing a false skip
- jsonl is the single source of truth with no file locking, so two concurrent classify runs on the same specId could race and interleave writes
- Replaying a cached reply after restart means the posted comment can go stale relative to later edits on the issue, since we never re-check the issue content once classified

## Contract

| facade | promise |
| ------ | ------- |
| pnpm classify --spec-id <specId> | Single pass over all issues visible to the configured GitHub service (mock or prod, decided by existing tracker env config). For each issue: skip if already classified (see detection rule below), otherwise classify, comment, and upsert. Exits 0 on a clean pass, non-zero if any issue failed to classify or comment. |
| GENERATED_DIR env var (default: .generated) | Root directory for classifier output. The classifier reads/writes only under $GENERATED_DIR/<specId>/classifications.jsonl. Never hardcodes .generated, so callers can redirect to a temp dir. |
| $GENERATED_DIR/<specId>/classifications.jsonl | One JSON object per line, one line per known issue, keyed by issueId. Upserted, never truncated wholesale. Shape: { issueId, reply, priority, effortEst, meta: { timeInMs, etConsumed, llmConfig } }. |
| Comment marker: first line of every classifier-authored GitHub comment is exactly `<!-- classifier:<specId>:<issueId> -->` | Any comment on an issue starting with this exact marker for that issueId is proof the issue was already classified. Presence of this marker (not comment count, not text similarity) is the sole detection signal. |
| stdout lines: `CLASSIFIED issueId=<id>`, `SKIPPED issueId=<id>`, `REPOSTED issueId=<id>` | One line per issue processed, printed in the order issues were evaluated. REPOSTED means: no marker comment found on GitHub, but a jsonl entry existed, so the cached reply was re-posted with no LLM call. |

## ACCS — general flow

1. Resolve repo root and load .env for GitHub base URL / owner / repo / mock start command, all overridable, none hardcoded to .generated
2. Create an isolated temp dir via mktemp and point GENERATED_DIR at it for every classify invocation, trap cleanup to remove it and kill the mock on exit no matter how the script ends
3. Start the mock GitHub service in the background and poll its issues endpoint until it responds, capturing its PID so it can be killed later
4. List the issues the mock currently serves so we know which issueIds to check markers and jsonl entries against
5. Run `pnpm classify --spec-id 003-issues-classifier` once against the fresh mock + empty temp jsonl, capture stdout and exit code
6. Assert: exit 0, no REPOSTED lines yet, jsonl file exists under the temp dir with an entry per issue, and every issue now has a marker comment visible via the mock's GitHub API
7. Kill the mock process and start a brand-new instance to simulate the in-memory GitHub losing all comments, and confirm the markers are indeed gone before continuing
8. Run classify a second time with the same temp GENERATED_DIR (jsonl untouched, GitHub wiped)
9. Assert: exit 0, no CLASSIFIED lines (proves no LLM was called again), at least one REPOSTED line, jsonl line count unchanged from pass one (upsert not rewrite), and every issue's marker comment is visible again via the GitHub API
10. Stop the mock, and on exit (success or failure) always kill any leftover mock process and delete the temp GENERATED_DIR so the repo's real .generated is never touched
11. Exit 0 only if every assertion above held; otherwise print [FAIL] diagnostics to stderr and exit 1
