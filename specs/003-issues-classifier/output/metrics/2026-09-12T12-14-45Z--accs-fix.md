## ACCS — general flow

1. Spin up a fully isolated temp GENERATED_DIR (never touching the repo's real .generated) and start the mock GitHub on MOCK_GITHUB_PORT
2. Pull the mock's issue id set from flat GET /issues, fail fast if it's empty
3. Run 'pnpm classify --spec-id <specId>' once, capture stdout and exit code, then check classifications.jsonl exists, has no dupes, and its issueId set matches the mock exactly
4. Validate every jsonl entry's shape: priority 0-5, effortEst 0-3 (forced 0 when priority is 0), non-empty reply, and meta.timeInMs/etConsumed/llmConfig all populated
5. Confirm each issue got exactly one CLASSIFIED/SKIPPED/REPOSTED stdout line
6. For each issue, fetch GET /issues/:id/comments, find the comment whose first line is the exact marker, then confirm the priority number appears as a whole token on a priority-labeled line and the effort number likewise on an effort-labeled line (word-boundary match, not a bare substring grep, so stray digits elsewhere in the prose/table can't fake a pass)
7. Snapshot the jsonl, kill and restart the mock to simulate GitHub memory loss, then run the classifier again
8. Confirm every issue now reports REPOSTED with no LLM re-invocation, the jsonl is byte-for-byte unchanged (meta included), and the comments re-appear and still pass the same marker + priority/effort line checks
