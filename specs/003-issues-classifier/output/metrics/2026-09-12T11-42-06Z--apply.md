## Bugs and loopholes in the spec or the ACCS

- **Coverage** "curl -s "$GH_BASE/repos/$GH_OWNER/$GH_REPO/issues/$issue_id/comments" \" — src/mock-github/server.ts only registers ISSUE_COMMENTS_PATH = /^\/issues\/(\d+)\/comments\/?$/ (the flat route). There is no /repos/:owner/:repo/issues/:id/comments route — I confirmed this both by reading server.ts and by live curl (repo-scoped path 404s, flat path 200s). marker_present_on_github can therefore never see a comment, so every phase-1 and phase-2 marker assertion fails no matter what the classifier posts.
- **Method** "GH_BASE="${GITHUB_API_BASE_URL:-http://localhost:4000}"" — src/mock-github/main.ts binds to MOCK_GITHUB_PORT (default 4123), and GITHUB_API_BASE_URL is defined nowhere in .env.example or the app. Unless a real .env happens to set it correctly, the health-check loop polls the wrong port for 60s and fails before any classify pass runs.
- **Method** "GH_OWNER="${GITHUB_OWNER:-mock-owner}"" — GITHUB_OWNER has no producer anywhere in the codebase (not in .env.example, not read by any src file). Worse, GH_REPO falls back to the pre-existing GITHUB_REPO var, which src/issue-tracker/config.ts and .env.example both document as a combined "owner/repo" string substituted as one path segment elsewhere. If a real .env sets GITHUB_REPO that way, accs.bash's separate $GH_OWNER/$GH_REPO concatenation injects an extra slash and breaks the URL regardless of the comments-route issue above.

## Why it stopped

output/accs.bash constructs requests against a repo-scoped comments endpoint and a default port/env-var set that don't exist anywhere in src/mock-github or the rest of the app, so the check fails independent of how faithfully pnpm classify implements the enriched-spec's contract.
Rebuild output/accs.bash to target the mock's actual surface: use the flat /issues/:id/comments route for marker detection, default GH_BASE to the mock's real bind port (MOCK_GITHUB_PORT, 4123), and drop the invented GITHUB_OWNER var (or wire it and a non-conflicting repo var into .env.example/server.ts first).
