## What was built

Implemented pnpm classify (classifier.ts, classificationsStore.ts, classificationComment.ts, classifierConfig.ts, llmClassifier.ts, classifyMain.ts) with jsonl upsert under $GENERATED_DIR/<specId>/, marker-based comment detection, and env-driven LLM config defaulted in .env.robots/.env.example. The first classify pass works end-to-end (all 20 issues CLASSIFIED, comments verified against jsonl), but the ACCS fails on its second pass: after 'stop_mock'/'start_mock', issue 1 comes back SKIPPED instead of REPOSTED, meaning the mock's in-memory comment survived the restart.

## Decisions made outside the spec

- **CLI shape for classify command** pnpm classify --spec-id <specId>, single pass — matches enriched-spec facade and existing non-daemon SDD tooling style
- **LLM config env var names** CLASSIFIER_MODEL, CLASSIFIER_EFFORT, CLASSIFIER_THINKING, defaulted in .env.robots — enriched-spec fixed these names; defaults needed somewhere runnable out of the box
- **Comment table format for priority/effort** markdown table with explicit 'Priority' and 'Effort' labelled rows — keeps SKIPPED-path re-parsing symmetric with generation, and satisfies ACCS's line-matching regex

## Sent back

Redo the ACCS only.

## Bugs and loopholes in the spec or the ACCS

- **Method** "stop_mock() { [ -n "$MOCK_PID" ] && kill "$MOCK_PID" 2>/dev/null; wait "$MOCK_PID" 2>/dev/null; MOCK_PID="" }" — MOCK_PID is the pnpm wrapper's PID (from 'pnpm run mock-github &'), not the underlying tsx/node server; killing it can leave the actual mock-github process running and holding the port, so the second start_mock's readiness curl just talks to the still-alive first instance. That means the in-memory comment state never actually resets, so REPOSTED is unreachable for at least one issue and the ACCS fails deterministically regardless of classifier correctness.

## Why it stopped

The ACCS's mock-restart step (specs/003-issues-classifier/output/accs.bash, stop_mock/start_mock) does not reliably kill the mock-github child process, so the mock's in-memory comments survive across the 'restart', causing the second classify pass to see issue 1 as already-commented (SKIPPED) instead of memory-lost (REPOSTED). This conflicts with the spec's replay requirement, which assumes a real memory loss on mock restart.
Fix accs.bash to kill the actual mock server (e.g. use `kill -- -$(ps -o pgid= $MOCK_PID)` or run the mock directly via `tsx src/mock-github/main.ts` instead of through `pnpm run`, so MOCK_PID is the real server's PID) so the restart genuinely clears in-memory comments before the second pass.
