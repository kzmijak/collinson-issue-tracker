## What it was fixed after

The spec 002 implementation (mock-github server, terminal repaint/snapshot markers, comment endpoints, proactive tracker dedup) was already built and manually verified working correctly against the contract. The ACCS itself is critically broken: its check_snapshots() awk function never initializes lastN, so awk's implicit numeric-0 default makes the very first snapshot marker (n=0, which is correct) always fail as 'nonmonotonic', on every phase, for any implementation. I also fixed one stale test asserting the pre-port-change default of 4000 instead of 4123.

## ACCS — general flow

1. Only change vs the previous accs.bash: check_snapshots()'s awk now has a BEGIN block setting lastN=-1
2. Root cause was that lastN was left undeclared, so awk defaulted it to numeric 0 on first use
3. Since valid snapshot numbering starts at n=0 per the enriched contract, the first marker line (n=0) always tripped 'n<=lastN' (0<=0) and failed immediately, before any real assertion ran
4. With lastN initialized to -1, the first marker (n=0) correctly passes the monotonicity check (0 > -1), and the 'lastN >= 0' guards used elsewhere in the same script (to skip flush()/dup-checks before any marker has been seen) keep working as originally intended
5. No other logic, phases, or assertions were touched - this was the single reported defect and everything else in the script matches the contract as implemented and manually verified
