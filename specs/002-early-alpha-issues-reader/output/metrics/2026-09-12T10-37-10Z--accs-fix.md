# ACCS fix report — 002-early-alpha-issues-reader

2026-09-12T10:36:29.044Z · ACCS rewritten · 42s · 82,910 ET

## What it was fixed after

The duplicate/cap-check awk block relies on gawk's 3-arg match(s,r,arr) extension, which errors out under plain POSIX awk/mawk (common default on Debian/Ubuntu), so the whole duplicate-detection guard can silently break the script. Several JSON reads use whitespace-sensitive grep patterns instead of a JSON parser, so they'll break the moment the service pretty-prints output, which the contract never rules out.

## ACCS — general flow

1. Load .env, set port/base-url defaults, force MOCK_GITHUB_BUFFER_CAP=500 for full-coverage checks, free the port from any stale process, and register cleanup-on-exit.
2. Start pnpm mock-github, poll /issues until it responds.
3. Read the initial /issues payload with python3 (not grep) to confirm issues exist, none have comments yet, and capture the first issue's id and total count.
4. Wait 4s for the linear load, re-fetch /issues, confirm the count grew via python3-parsed length.
5. Run a single-pass POSIX-awk scan (check_snapshots) over the mock's stdout log: track snapshot markers, flag any issue id repeating within one snapshot, and flag any block exceeding the buffer cap or missing the '...' truncation line. Uses 2-arg match()+substr()/gsub() only, no gawk-only 3-arg match().
6. POST a 'Hello World!' comment to the first issue via curl, confirm the '[comment] issue #<id> +1 from QA Harness' log line appears, and confirm the comment shows up in a fresh /issues fetch via python3 JSON parsing.
7. Start pnpm issues-tracker, let it run one full pass, then kill it.
8. Fetch /issues again and use python3 to assert: first issue has exactly 2 comments (original + exactly one tracker comment with the right body), every other issue has 0 or 1 comment and any comment present is the tracker's, and no issue id repeats in the response.
9. Re-run the single-pass awk snapshot check over the full accumulated log to catch any duplicate/cap violation introduced by the tracker run.
10. Print PASS and exit 0, or fail fast with a labeled message (and run cleanup) at the first violated expectation.
