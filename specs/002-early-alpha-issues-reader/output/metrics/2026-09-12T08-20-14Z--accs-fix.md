# ACCS fix report — 002-early-alpha-issues-reader

2026-09-12T08:19:20.113Z · ACCS rewritten · 55s · 90,813 ET

## What it was fixed after

The ACCS script skips two explicit accs.md checks — the zero-comments state right after mock startup, and that already-loaded issues other than #1 end up with exactly 1 comment — so a broken tracker or broken initial state could still pass.

## ACCS — general flow

1. Run 001's accs.bash as a gate; bail out unless it exits 0, then kill it and start fresh
2. Boot pnpm mock-github, capture stdout to mock.log, and immediately confirm every early issue block shows (0) comments
3. Wait out the 4s streaming window and confirm the issue count grew, snapshot numbers are strictly increasing with no dupes, and no issue repeats inside a single snapshot
4. POST a comment to issue #1 with no author field, confirm 201 + the 'by Anonymous' mutation log line, then snapshot the pre-tracker state and record which issue numbers already existed
5. Start pnpm issues-tracker, wait a few poll cycles, then re-slice the newest snapshot block
6. Check issue #1 has 2 comments including a 'been here' one, and every other pre-existing issue number has exactly 1 comment that says 'been here', leaving not-yet-streamed issues unchecked
7. Re-run the duplicate-issue-per-snapshot scan once more over the whole log before declaring PASS
