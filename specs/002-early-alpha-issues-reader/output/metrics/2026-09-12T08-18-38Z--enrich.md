# Enrichment report — 002-early-alpha-issues-reader

2026-09-12T08:17:03.981Z · written · 1m 34s · 135,624 ET

## Assumptions made

- **How should ACCS actually observe the terminal repaint discipline?** Capture stdout to a file when accs.bash spawns pnpm mock-github, then grep for the ANSI clear + Snapshot header + issue blocks + mutation log line, addressing the reviewer's gap that this was previously unverified
- **What exact HTTP path/method for the mutation?** POST /issues/:number/comments, mirroring 001's read-side numbering

## Expected drawbacks

- Requiring ACCS to capture stdout via process redirection (not a log file) means the check is coupled to how accs.bash spawns the process — acceptable since accs.bash owns that spawn.
- Snapshot counter is a new observable surface invented for testability, not something a real GitHub CLI would have — fine for a mock, but it's contract surface that has to keep working forever now.

## Contract

| facade | promise |
| ------ | ------- |
| pnpm mock-github | Starts the in-memory stateful mock GitHub service, seeded like 001 (60% at t=0, rest streamed over 10s), plus the comment mutation endpoint. All terminal output goes to stdout only — no separate log file. |
| POST http://localhost:${MOCK_GITHUB_PORT}/issues/:number/comments  body: { "author"?: string, "body": string } | Appends a comment in memory, returns 201 with { author, body, createdAt }. author defaults to "Anonymous" if omitted. 404 if issue doesn't exist yet. |
| MOCK_GITHUB_PORT (.env) | Port the mock GitHub HTTP server listens on. Same var/default as 001. |
| mock GitHub stdout — snapshot header | Every repaint (on startup and after every accepted comment mutation) begins by writing the ANSI clear sequence `\x1b[2J\x1b[H` immediately followed by a line `Snapshot #<n>` where n is a strictly increasing integer starting at 1, incremented exactly once per repaint. No two snapshots share a number; ACCS can split captured stdout on this header to isolate each repaint. |
| mock GitHub stdout — issue block | Within each snapshot, every currently-known issue is printed exactly once, in the format `Issue #<number>: (<commentCount>)` then `Title:`, `Content:`, `Comments:`, each comment as `  - [<author>]` + indented body line, blank line between comments — matching the spec example. |
| mock GitHub stdout — mutation log line | Immediately before the repaint triggered by an accepted comment, one line is written: `New comment on issue #<number> by <author>`, appearing once between the previous snapshot's block and the next snapshot header. |
| pnpm issues-tracker | Polls MOCK_GITHUB_PORT's issue list; for every issue where no existing comment has author "GitHub Issues Tracker", posts body "I've been here!" author "GitHub Issues Tracker" via the mutation endpoint. |
| ISSUES_TRACKER_POLL_INTERVAL_MS (.env) | Milliseconds between tracker poll cycles. Defaults to 1000 if unset. |
| specs/001-.../output/accs.bash | Unchanged entry point from 001, used as a precondition gate — run first, tear down its process only if it exits 0. |

## ACCS — general flow

1. Resolve repo root from the script's own path and load .env for MOCK_GITHUB_PORT / ISSUES_TRACKER_POLL_INTERVAL_MS defaults
2. Locate and run 001's accs.bash as a gate; on failure kill any stray mock/tracker processes and exit 1, on success kill leftover 001 processes and continue
3. Start `pnpm mock-github`, redirect stdout to a log file, and record the spawn timestamp
4. Check the issues list is reachable and non-empty right after spawn, and scan the log so far for duplicate Issue # lines within any single Snapshot block
5. Sleep until 4s have passed since spawn, then confirm the issue-line count grew, snapshot numbers are present, strictly increasing and unique
6. POST 'Hello World!' as curl-user to issue #1 via curl, confirm 201, confirm the mutation log line and the next snapshot's issue #1 block shows commentCount 1
7. Start `pnpm issues-tracker`, wait a few poll cycles based on ISSUES_TRACKER_POLL_INTERVAL_MS
8. Confirm issue #1 ends at commentCount 2, other issues show the 'I've been here!' comment, and re-scan the whole log once more for any duplicate Issue # line inside a single snapshot
9. Print PASSED and exit 0; trap always kills the mock and tracker background processes on exit
