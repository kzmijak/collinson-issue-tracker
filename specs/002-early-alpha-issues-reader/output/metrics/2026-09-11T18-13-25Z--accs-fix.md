## What it was fixed after

The ACCS script never checks the GitHub Service Terminal's stdout at all, so it can pass even if comment counts, the new-comment log line, and full repaints are never implemented. That's a core spec.md requirement left completely unverified.

## ACCS — general flow

1. Run spec 001's accs.bash inline and abort immediately if it fails; no leftover kill calls after wait since the process is already reaped
2. Boot the mock GitHub service in mock mode, redirecting its terminal stdout to /tmp/accs002-mock.log, and record its spawn timestamp
3. Poll /issues until the mock is reachable, confirm issues exist and none have comments yet
4. Boot the proactive tracker against the same mock instance
5. Post a 'Hello World!' curl comment on the first issue
6. Sleep until 4s have elapsed since mock spawn (plus a short buffer for the next repaint tick)
7. Verify via HTTP that the first issue has 2 comments (curl + tracker) and all others have at most 1, which must be the tracker's 'I've been here!' marker
8. Verify via the mock's captured stdout log that every known issue got a comment-count line, that the first issue was shown at its final count of 2, that a 'New comment on issue #<n>' line was printed at least once per comment actually posted, and that comment-count lines outnumber a single issue-list's worth of entries (proving repeated full repaints, not silence or a one-shot print)
