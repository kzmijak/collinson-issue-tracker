# Enrichment report — 002-early-alpha-issues-reader

2026-09-12T07:24:48.966Z · written · 1m 49s · 174,646 ET

## Assumptions made

- **What does a curl-posted comment display as its author when none is given?** 'Anonymous', since the spec's example only shows named/tracker authors and accs.md's curl call passes no author
- **How does the tracker's comment carry its distinct author name through the existing body-only POST contract?** extend POST with an optional 'author' field, tracker always sets it to 'GitHub Issues Tracker'
- **How should ACCS reliably isolate each repaint cycle in the log?** explicit '--- REPAINT ---' marker line at the start of every repaint, rather than inferring boundaries from incidental non-matching lines

## Expected drawbacks

- Full title+content+all-comments reprint every cycle is verbose and gets slower as issue/comment counts grow — acceptable for this spec's scale and timeframe, would need diffing or paging later.
- Adding 'author' to POST is a contract change from the prior approved round — any external caller relying on body-only POST needs updating, but nothing outside this spec calls it yet.

## Contract

| facade | promise |
| ------ | ------- |
| env GITHUB_MODE | Only 'mock' is accepted. Tracker exits non-zero with a stderr message on anything else, before any network call. |
| env MOCK_GITHUB_PORT (default 4001) | Port the mock service binds its HTTP API and terminal to. |
| env ISSUE_TRACKER_POLL_MS (default 1000) | Interval the tracker polls the mock service. |
| pnpm mock-github | Loads 60% of mock issues immediately, remaining 40% linearly over 10s, exposes the HTTP API below, prints the GitHub Service Terminal to stdout. |
| pnpm issue-tracker:proactive | Polls MOCK_GITHUB_PORT on ISSUE_TRACKER_POLL_MS and posts 'I've been here!' once per untouched issue. |
| GET http://localhost:<PORT>/issues | JSON array, each item at least { number, title, body, comments_count }. |
| GET http://localhost:<PORT>/issues/:number/comments | JSON array, each item at least { author, body }. |
| POST http://localhost:<PORT>/issues/:number/comments  body: { body: string, author?: string } | Appends a comment, returns 201. Missing author is stored and printed as 'Anonymous'. Bumps comments_count on the next GET. The tracker always sends author: 'GitHub Issues Tracker' on its own posts. |
| stdout line: '--- REPAINT ---' | Printed as the first line of every terminal repaint, before the cleared screen is redrawn — an unambiguous block delimiter for log parsing. |
| stdout block per issue: 'Issues #<number>: (<comments_count>)\nTitle: <title>\nContent: <body>\nComments:\n  - [<author>]\n    <comment body>\n' (repeated per comment, blank line between issues) | Exact per-issue print shape on every repaint, full detail, never a diff. |
| stdout line: 'New comment on issue #<number>' | Printed exactly once, immediately when any comment (curl or tracker) is accepted, outside the repaint block. |
| comment body: 'I've been here!' / author: 'GitHub Issues Tracker' | Exact strings the tracker writes, once, on the first poll cycle it sees an issue it hasn't posted to yet. |

## ACCS — general flow

1. locate and run spec 001's accs.bash; if it fails, log and abort this whole script (self-terminate)
2. export GITHUB_MODE=mock, then spawn pnpm mock-github in the background and record its spawn timestamp
3. poll /issues until the mock server answers, then assert issues exist and none carry comments yet
4. spawn pnpm issue-tracker:proactive in the background
5. curl-POST 'Hello World!' onto the first issue returned by /issues
6. sleep out the remaining time until exactly 4s have elapsed since the mock service spawn
7. re-fetch /issues: assert issue #1 has comments_count 2 containing both 'Hello World!' and the tracker's 'I've been here!' from 'GitHub Issues Tracker'
8. assert every other issue has comments_count 0 or 1, and any that have 1 carry the exact tracker comment/author pair
9. kill both background processes on exit (trap) and exit 0 only if every assertion passed
