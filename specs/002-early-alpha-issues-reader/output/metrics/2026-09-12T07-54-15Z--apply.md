# Implementation report — 002-early-alpha-issues-reader

2026-09-12T07:45:43.809Z · budget-exhausted after 1 round · 8m 32s · 1,357,040 ET

## What was built

Rewrote the mock GitHub comment endpoint, terminal, and proactive tracker to match the re-enriched contract (author field, createdAt, 404/400 handling, comment-triggered full repaint, comments-derived touch detection) since the prior implementation predated those amendments and matched almost none of them. bash specs/002-early-alpha-issues-reader/output/accs.bash exits 0, confirmed on two consecutive runs, and pnpm typecheck/lint/format/test all pass (209 tests green).

## Decisions made outside the spec

- **pnpm script name for the tracker facade** renamed issue-tracker:proactive to issues-tracker in package.json — the contract table and accs.bash both call it pnpm issues-tracker; nothing else referenced the old key outside its own log strings
- **env var name for the tracker's poll cadence** renamed ISSUE_TRACKER_POLL_MS to ISSUES_TRACKER_POLL_INTERVAL_MS in code and .env.example — matches the exact name given in the contract table; the old name wasn't referenced anywhere else
- **whether GET /issues should expose full comments, not just a count** added a comments array alongside the existing comments_count field — accs.bash reads .comments per issue and the tracker needs per-comment author to re-derive touch state; nothing in the contract forbids extending the read shape
- **how the tracker decides an issue is already touched** derive it from scanning issue.comments for author 'GitHub Issues Tracker' on every poll, replacing the prior private in-memory Set — the enriched spec's own 'Decisions already made' section requires this; the existing code contradicted it
- **should the comment endpoint validate empty bodies / missing issues** 400 on empty body, 404 on a non-existent issue number — both were the enriched spec's own recommended answers to its 'Open questions' section, left unimplemented by the prior code

## Bugs and loopholes in the spec or the ACCS

- **Coverage** "mock GitHub terminal output | On process start and after every accepted comment mutation, the terminal is fully cleared (no scrollback append) and the entire current issue list is reprinted top to bottom" — accs.bash never inspects stdout from the mock-github or tracker processes — it only curls JSON endpoints. A terminal that never repaints, or repaints in the wrong format, would still pass the ACCS. This means the whole terminal-formatting half of the contract table is currently unverifiable by the acceptance check.
- **Coverage** "Tracker's own service state (which issues it's touched) is purely in-memory, re-derived from reading each issue's existing comments rather than a private log" — This re-derivation reopens a race the prior private-Set implementation closed: two overlapping poll ticks (a slow POST outlasting the poll interval) could both see 'untouched' and double-comment. accs.bash's single 4-second, 1000ms-interval, localhost run can't trigger this, so the race exists in the code but has no accs coverage that would catch it.
