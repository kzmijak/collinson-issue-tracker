## What it was fixed after

The ACCS never actually confirms a repaint prints every issue together in one shot — it only checks that each issue line shows up somewhere in the log at some point, so a diff-style repainter (explicitly forbidden by the contract) would still pass.

## ACCS — general flow

1. Run spec 001's accs.bash in its own session, wait for it, kill its process tree, abort if it failed
2. Verify the mock-only hard gate: tracker must exit non-zero and make no network calls with GITHUB_MODE unset or set to 'prod', before anything is listening on the port
3. Boot the mock GitHub service, wait for /issues to respond, confirm issues loaded with zero comments, note the lowest issue number
4. Boot the proactive tracker against the mock
5. POST a 'Hello World!' comment on the first issue via curl
6. Sleep until 4s have elapsed since the mock service spawned, plus a short settle buffer
7. Check final HTTP state: first issue has 2 comments (curl + tracker marker), every other issue has at most 1 and if 1 it's the tracker's 'I've been here!' marker
8. Group the terminal log into repaint blocks (maximal runs of 'Issue #<n>: <count> comment(s)' lines) and require at least 2 blocks, proving repeated full repaints instead of a single dump
9. Assert the FINAL repaint block alone contains every currently-loaded issue exactly once with the count matching live HTTP state and the right total line count - this is what actually rules out a diff/append-style repainter
10. Assert 'New comment on issue #<n>' lines were logged at least once per comment, including for the first issue
