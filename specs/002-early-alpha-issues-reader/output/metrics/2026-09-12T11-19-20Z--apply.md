## Bugs and loopholes in the spec or the ACCS

- **Method** "if (n<=lastN) { print "FAIL nonmonotonic " n " after " lastN; bad=1; exit }" — lastN is never initialized (no BEGIN block), so awk treats it as numeric 0. Since snapshot numbering correctly starts at 0 per the enriched contract, the very first marker line always satisfies n<=lastN (0<=0) and the script exits FAIL immediately, before any real assertion runs. Reproduced in isolation with a two-line synthetic snippet (no server involved): 'FAIL nonmonotonic 0 after '. This means check_snapshots(), called in every phase of accs.bash, can never succeed regardless of what src/ implements.

## Why it stopped

accs.bash's check_snapshots() awk helper always fails on the first snapshot marker (n=0) due to an uninitialized lastN defaulting to numeric 0, so the ACCS can never exit 0 for any implementation.
Add `BEGIN { lastN = -1 }` to the awk script inside check_snapshots() in specs/002-early-alpha-issues-reader/output/accs.bash, then re-run bash specs/002-early-alpha-issues-reader/output/accs.bash.
