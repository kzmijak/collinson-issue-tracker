# Implementation report — 002-early-alpha-issues-reader

2026-09-11T18:34:07.011Z · converged after 1 round · 7m 57s · 1,264,499 ET

## What was built

Added the mutation endpoint (GET/POST /issues, /issues/:number/comments) and a repainting GitHub Service Terminal to the mock GitHub service, plus a new Proactive Issues Tracker that mock-mode-gates itself and drops a one-time 'I've been here!' comment per undiscovered issue. specs/002-early-alpha-issues-reader/output/accs.bash passes on repeated runs, and pnpm typecheck/lint/format:check/test all pass.

## Decisions made outside the spec

- **cadence of the GitHub Service Terminal's repaint loop** fixed 1000ms interval, independent of ISSUE_TRACKER_POLL_MS — the contract only says every poll tick and every accepted comment trigger a repaint, and the mock service has no 'poll' of its own — a steady 1s tick is the simplest thing that gives the ACCS multiple repaint blocks inside its 4s window
- **how to make repaint cycles distinguishable in the log** print a timestamped header line before each block of Issue #n lines — without a non-matching separator, back-to-back full repaints of the same issue list are indistinguishable from one continuous list when read back later
- **what happens to an issue whose marker-comment POST fails** un-touch it so the next poll retries, rather than giving up permanently — no persistence exists anywhere in this spec, so silently abandoning an issue forever on one transient failure seemed worse than a bounded retry loop

## Bugs and loopholes in the spec or the ACCS

- **Scope** "default mock port - 4001" — Applying this as the code default would change what port `pnpm mock-github` binds to when MOCK_GITHUB_PORT is unset, which breaks spec 001's accs.bash (it never sets MOCK_GITHUB_PORT itself and hardcodes port 4123) — and spec 002's own ACCS runs spec 001's ACCS first as a gate. I left the code default at 4123 so both ACCS suites keep passing; spec 002's own runs are unaffected since its accs.bash always sets MOCK_GITHUB_PORT explicitly.
