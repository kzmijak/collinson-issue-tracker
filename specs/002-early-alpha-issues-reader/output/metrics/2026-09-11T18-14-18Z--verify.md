## Summary

The mock-only hard gate is spelled out in the contract and behaviour table but accs.bash never actually tries to start the tracker with a bad or missing GITHUB_MODE, so an implementation that skips the gate would still pass.

## Scope of the fix

Redo the ACCS only.

## Why rejected

- **Coverage** "| GITHUB_MODE unset or set to anything other than 'mock' | tracker exits non-zero immediately, no network calls made |" — accs.bash always launches the tracker with GITHUB_MODE=mock explicitly and never exercises the unset/invalid case, so the single scariest requirement in this spec ('ONLY MOCK INSTANCES!') has zero enforcement check in the ACCS.

## Should fix

- **Method** "bash "$SPEC001" &
SPEC001_PID=$!
wait "$SPEC001_PID"" — accs.md says 'if it succeeds, terminate only the 001 script' but the script never kills anything after wait returns — it silently relies on spec 001's own trap-cleanup to have torn down its background mock/tracker, which isn't stated anywhere in this doc and will collide on port 4001 if that assumption is wrong.

## Worth to consider

- **Scope** "FIRST_ISSUE=$(echo "$ISSUES_JSON" | jq '[.[].number] | sort | .[0]')" — FIRST_ISSUE is pinned from whatever loaded in the initial 60% burst, so it may not be issue #1 by any human-meaningful ordering — fine for the check, but worth knowing this isn't literally 'the first issue' in intake order.
