# Verification report — 002-early-alpha-issues-reader

2026-09-11T18:11:42.686Z · rejected · 52s · 77,974 ET

## Summary

The ACCS script never checks the GitHub Service Terminal's stdout at all, so it can pass even if comment counts, the new-comment log line, and full repaints are never implemented. That's a core spec.md requirement left completely unverified.

## Scope of the fix

Redo the ACCS only.

## Why rejected

- **Coverage** "GitHub Service Terminal prints comment counts per issue and a log line per new comment, fully repainting each cycle" — This is listed under 'Done when' in the enriched spec, but accs.bash redirects mock stdout to /tmp/accs002-mock.log and never inspects that file for the 'Issue #<n>: <count> comment(s)' or 'New comment on issue #<n>' lines. A build with a silent or broken terminal would still pass ACCS.

## Should fix

- **Method** "kill -- -"$SPEC001_PID" >/dev/null 2>&1
  kill "$SPEC001_PID" >/dev/null 2>&1" — These kills run after 'wait' has already returned, so the process is already dead — harmless here but reads like leftover cleanup logic that should either be removed or moved before the wait for clarity.

## Worth to consider

- **Scope** "for i in $(seq 1 50); do
  curl -s -o /dev/null "$BASE/issues" && break
  sleep 0.1
done" — Readiness polling can eat up to 5s of the 4s budget before the 4s-since-spawn timer is even evaluated, so on a slow machine REMAINING could already be negative — script still works (skips the sleep) but the 4s window assumption gets tight.
