# Verification report — 002-early-alpha-issues-reader

2026-09-12T10:35:41.203Z · rejected · 48s · 80,767 ET

## Summary

The duplicate/cap-check awk block relies on gawk's 3-arg match(s,r,arr) extension, which errors out under plain POSIX awk/mawk (common default on Debian/Ubuntu), so the whole duplicate-detection guard can silently break the script. Several JSON reads use whitespace-sensitive grep patterns instead of a JSON parser, so they'll break the moment the service pretty-prints output, which the contract never rules out.

## Scope of the fix

Redo the ACCS only.

## Why rejected

- **Method** "if (match($0, /^Issues #([0-9]+):/, m)) {" — match() with a third capture-array argument is a gawk extension, not POSIX awk. If the box's default `awk` is mawk/one-true-awk (very common on Debian/Ubuntu), this line throws a syntax/runtime error and check_snapshots never runs the dup check it exists for, which is the one thing accs.md says must terminate with an error if violated.
- **Method** "COUNT1=$(echo "$FIRST" | grep -o '"id"' | wc -l)" — Nothing in the contract guarantees compact, no-space JSON, so a serializer that emits '"id": 5' (space after colon) or pretty-printed output breaks every grep-based extraction (COUNT1, COUNT2, FIRST_ID) in the script even when the implementation is correct, stalling the dev agent on a false failure.

## Should fix

- **Coverage** "FIRST_BLOCK=$(echo "$FINAL" | tr '}' '}\n' | grep -A2 "\"id\":$FIRST_ID" || true)" — This line computes a value that's never read afterward (the real check is the python3 block below it) — dead code that just adds noise and a second fragile grep pattern for no benefit.

## Worth to consider

- **Coverage** "export MOCK_GITHUB_BUFFER_CAP=500" — Truncation/'...' behavior from the contract is never exercised since the cap is forced to 500 for the whole run — correct per accs.md's instruction to size the buffer to fit everything, but worth knowing the default-cap and truncation table in the enriched spec stay unverified by this ACCS.
