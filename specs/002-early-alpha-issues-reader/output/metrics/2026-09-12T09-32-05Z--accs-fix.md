## What it was fixed after

The previous blocker (comment-added log line never checked) is now fixed, but the tracker sweep step only guards against double-touching and checks the first issue's count — it never asserts that any issue besides the first actually received the tracker's comment, so a tracker that does nothing to everyone else would still pass.

## ACCS — general flow

1. Force mock-only env, run spec 001's accs.bash as a smoke test, abort if it fails
2. Boot pnpm mock-github with a wide MOCK_GITHUB_BUFFER_CAP=500, log its stdout to mock-github.log
3. Confirm issues load with zero comments, then confirm growth by 4s, checking snapshot integrity (no dup ids, no cap overflow, truncated blocks end in '...') after every read
4. POST 'Hello World!' on the first issue via curl, confirm the immediate '[comment]' log line, confirm the issue now has exactly 1 comment
5. Snapshot the full issue list right here as ISSUES_C - this is the 'pre-tracker' baseline
6. Run pnpm issues-tracker for a few poll cycles, then kill it
7. Snapshot issues again as ISSUES_D, confirm first issue has 2 comments, confirm tracker's comment got logged, confirm no issue has more than one tracker comment and bodies are correct
8. Coverage check: every issue that was already present in ISSUES_C (before the tracker ran) must now have exactly one tracker comment in ISSUES_D - only issues absent from ISSUES_C (late loads) may still have zero
9. Run the snapshot integrity sweep one final time, then exit 0
