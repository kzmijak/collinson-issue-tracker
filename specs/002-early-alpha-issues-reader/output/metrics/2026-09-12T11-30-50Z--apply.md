## What was built

Most of spec 002 was already implemented; I found and fixed two real implementation bugs that were making the ACCS fail (a stray ANSI escape line corrupting snapshot parsing, and a blank MOCK_GITHUB_URL silently zeroing out the tracker's poll target). `bash specs/002-early-alpha-issues-reader/output/accs.bash` now exits 0, run twice back to back, with `pnpm test`/`lint`/`typecheck` all clean.

## Decisions made outside the spec

- **how to stop the ANSI clear code corrupting piped snapshot parsing** only emit \x1B[2J\x1B[H when process.stdout.isTTY is true — the escape line has no business in a redirected/captured log and the contract's marker-line format has no room for it either
- **how to print stdout content while satisfying no-console-log lint rule** added a writeLine() helper using process.stdout.write directly instead of console.log — repo eslint only allows console.warn/error, and the contract requires these lines on stdout not stderr

## Bugs and loopholes in the spec or the ACCS

- **Coverage** accs.bash's check_snapshots awk parser attributes any unrecognized line between two ===SNAPSHOT markers to the earlier snapshot rather than treating it as noise. It works correctly now that the implementation emits nothing extraneous between markers, but it's a sharp edge if a future change ever needs another stdout log line outside of a repaint.
