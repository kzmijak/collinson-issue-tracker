## ACCS — general flow

1. Free the mock port, then run a throwaway mock-github instance with MOCK_GITHUB_BUFFER_CAP=3 and assert the log contains a literal '...' truncation line and no snapshot exceeds 3 lines - kill it and free the port again
2. Run another throwaway mock-github instance with no cap override (no tty in this context) and assert every snapshot stays within the hard 200-line fallback cap
3. Start the real coverage run with MOCK_GITHUB_BUFFER_CAP=500 as before: verify fresh issues have zero comments, snapshots are duplicate-free and strictly increasing, and issue count grows over the first ~4s
4. POST 'Hello World!' onto the first issue, wait past the repaint latency bound, and confirm that issue now shows exactly 1 comment and snapshots stay valid
5. Run pnpm issues-tracker for 6s, then confirm the first issue has 2 comments (manual + tracker), every other issue has at most 1, all tracker comments have the exact author/body, and snapshots are still duplicate-free
6. Clean up: kill any spawned processes, free the port by lookup (never by matching a command string), remove temp logs
