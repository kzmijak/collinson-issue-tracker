## What it was fixed after

The mock-only hard gate is spelled out in the contract and behaviour table but accs.bash never actually tries to start the tracker with a bad or missing GITHUB_MODE, so an implementation that skips the gate would still pass.

## ACCS — general flow

1. Run spec 001's accs.bash in its own session (setsid) and wait for it, then explicitly kill that session's whole process group so we never rely on its internal cleanup having freed port 4001
2. Before touching the mock service, run the tracker twice with GITHUB_MODE unset and GITHUB_MODE=prod under a 3s timeout, and require both runs to exit non-zero (not via timeout) and to leave no connection-error traces in their logs, proving the mock-only gate runs before any HTTP call
3. Boot the mock github service and confirm issues load with zero pre-existing comments
4. Boot the proactive tracker against the mock and post a 'Hello World!' curl comment on the first issue
5. Wait until 4s have elapsed since the mock spawn, then read final issue/comment state
6. Assert first issue has exactly 2 comments (curl + tracker marker) and every other issue has at most 1, and that single comment is the tracker's marker
7. Assert the terminal log shows a comment-count line per issue, the first issue's final count, per-comment 'New comment' log lines, and multiple full repaint cycles
