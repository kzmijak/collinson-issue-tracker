## Bugs and loopholes in the spec or the ACCS

- **Method** "SNAP_LINES=$(wc -l < "$TRACKER_LOG")
cp "$TRACKER_LOG" "${TRACKER_LOG}.snap"" — cp captures the full raw file including whatever unterminated status-bar fragment is mid-write at that instant (renderStatus() never emits a trailing newline). The later recheck extracts via `head -n "$SNAP_LINES"`, which by definition can never include bytes past the last complete line. These two extraction methods can never produce identical output as long as the tracker keeps an in-place (CR-redrawn, non-newline-terminated) status bar — which the spec explicitly requires — so this check fails on every run regardless of whether the tracker is actually append-only.

## Why it stopped

accs.bash's append-only step compares a `cp`-based raw snapshot (which always includes a trailing unterminated status fragment) against a `head -n`-based re-extraction (which can never include one), so it fails unconditionally against any implementation of the spec's required in-place status bar.
Change the append-only check in accs.bash to snapshot with `head -n "$SNAP_LINES" "$TRACKER_LOG" > "${TRACKER_LOG}.snap"` instead of `cp`, so both sides of the diff are built the same way.
