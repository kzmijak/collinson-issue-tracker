## Bugs and loopholes in the spec or the ACCS

- **Method** "REPO="${GITHUB_REPO:-repo}"" — accs.bash treats GITHUB_REPO as a bare repo name and concatenates it after a separate GITHUB_OWNER, but the project's own established convention (config.ts, .env.example: 'Repo is an env var; ex. kzmijak/collinson-issue-tracker') is that GITHUB_REPO holds the combined 'owner/repo' string. In an environment where GITHUB_REPO=owner/repo (as this sandbox has ambiently), accs.bash builds /repos/owner/owner/repo/issues, so mock-github never answers and the whole run fails at 'mock boot' with a route that actually works fine.
- **Coverage** "for i in $(seq 1 10); do
  if curl -s --max-time 5 -o "$HERE/first.json" -w '%{http_code}' "$URL" 2>/dev/null | grep -q '^2'; then" — The boot-detection loop and the mock's growth timer both run off the same wall clock (MOCK_START), but the loop can legitimately eat up to 10s before the first successful curl on a loaded machine. If that happens, the growth window (now correctly 10s per spec) can already be exhausted by the time TOTAL1 is captured, so the later 'TOTAL2 > TOTAL1' assertion is structurally unsatisfiable even though the mock is growing exactly as specified.
- **Method** "[ -n "$MOCK_PID" ] && kill "$MOCK_PID" >/dev/null 2>&1" — kill only signals the top-level pnpm wrapper PID, not its sh -c tsx / node descendants, so a failed or interrupted run leaves live node processes holding write offsets into the recycled tracker.accs.log/mock.accs.log files. The next run's truncation of those same files then produces NUL-byte holes when the orphan next writes, breaking grep-based assertions for reasons unrelated to the tracker's actual output.

## Why it stopped

accs.bash's owner/repo URL assembly conflicts with the project's own combined GITHUB_REPO convention, and its boot-detection loop shares a clock with the growth timer it's asserting against — both are bugs in accs.bash, which is outside my src/harness+src/mock-github+src/issue-tracker+tests write boundary.
Have the operator patch specs/001-prototype-issues-reader/output/accs.bash: derive OWNER/REPO by splitting a single GITHUB_REPO='owner/repo' value instead of concatenating two vars, kill full process trees (e.g. `pkill -P $PID` or a process group) instead of single PIDs, and start the growth-comparison clock from the first successful curl rather than from process launch.
