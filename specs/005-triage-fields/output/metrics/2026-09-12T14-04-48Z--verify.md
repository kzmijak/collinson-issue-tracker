## Summary

The previous GENERATED_DIR/cleanup blocker is fixed by running an independent classify pass with its own mock and own GENERATED_DIR, but the comment cross-check silently skips every entry (and still prints PASS) when it can't resolve the issue-number field, which is a false-pass hole.

## Scope of the fix

Redo the ACCS only.

## Why rejected

- **Falsifiability** "ISSUE_NUMBER=$(echo "$line" | jq -r '.issueId // .issueNumber // .issue_number // empty')
  ...
  [ -z "$ISSUE_NUMBER" ] && continue" — If none of the three guessed field names exist on an entry, the loop silently skips comment verification for it with no failure recorded — if this happens for every entry, COMMENT_CHECK_FAIL stays 0, the script prints 'Comment tables match jsonl entries' and exits 0 without ever having checked a single comment. This lets a broken comment-table implementation pass the ACCS.

## Should fix

- **Method** "bash "$SPEC_003_ACCS"" — This runs a full mock+classify pass just to satisfy 'spec 003 still passes', then immediately runs a second full mock+classify pass for 005's own checks — doubling classifier ET cost and wall-clock time on every ACCS run for no added coverage.

## Worth to consider

- **Coverage** "COMMENTS_JSON=$(curl -sf "$BASE/issues/$ISSUE_NUMBER/comments" || echo '[]')" — On a curl failure this silently treats it as 'no comments' rather than a script error, which is fine for a missing-comment failure path but means transient network issues look identical to a genuine missing Kind column.
